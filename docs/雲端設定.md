# 雲端會員空間設定（Neon · 單人）

讓**持股、交易紀錄、訊號日誌與所有設定**永久保存並自動同步——重整、重新部署、換手機都還在。
未設定時 App 行為與原本完全一致（雲端區塊不顯示），所以**設定前可照常使用**。

---

## 一、建立 Neon 資料庫（約 3 分鐘，免費）

1. 到 <https://neon.com> 註冊 → **Create project**（區域選 **Singapore / ap-southeast** 離台灣近）。
2. 建好後，在 **Dashboard → Connection string** 複製連線字串，長這樣：
   ```
   postgresql://user:password@ep-xxxx-xxxx.ap-southeast-1.aws.neon.tech/dbname?sslmode=require
   ```
   （要含 `?sslmode=require`；用 **Pooled connection** 那條更穩。）

> 不用自己建表——App 第一次寫入時會自動建好 `tw_kv` 表。

---

## 二、把密鑰貼進 Streamlit Cloud（只能你本人做）

1. 到你的 App 頁 → 右上 **Manage app → Settings → Secrets**。
2. 貼上這三行（換成你的值）：
   ```toml
   DATABASE_URL = "postgresql://user:password@ep-xxxx.ap-southeast-1.aws.neon.tech/dbname?sslmode=require"
   APP_PASSCODE = "自己設一組密碼"
   ```
3. **Save** → App 會自動重啟。

---

## 三、使用

1. 重啟後，到 **「設定」頁最上面的「雲端帳號」** 登入：
   - 有設定 Google 登入（見第四節）→ 按 **「用 Google 登入」**，這台裝置會記住約 30 天，重新整理、關掉再開都不用重新登入。
   - 只有 `APP_PASSCODE` → 輸入密碼登入（只在這個分頁有效，重新整理要再輸入）。
2. 之後全部自動，不用按「存到雲端」：

| 資料 | 什麼時候上傳 | 換裝置 |
|---|---|---|
| 持股 | 在持股表編輯、或在交易計畫卡按「我已買進」之後 | 登入就載回 |
| 交易紀錄 | 記入賣出、編輯、匯入之後 | 登入就載回 |
| 訊號日誌 | 每次掃描有新的進場訊號之後 | 登入就載回 |
| 設定 | 總資金、月目標、單筆風險、選股條件、權重、成本、漲跌顏色等改了之後 | 登入就套用 |

- **只傳有變的**：內容沒改不會寫入；一條連線重複使用，不會每次存檔都等資料庫醒來。
- **頁首會顯示狀態**：「已同步 08:15」、「同步中斷，稍後自動重試」（資料先留在這個分頁，連上後自動補傳）。
- **另一台裝置改過**：每次換頁最多每 45 秒檢查一次，這台沒改的話會自動更新並跳出提示；「設定」頁的「立即檢查更新」可以馬上檢查。
- **兩台同時改**（例如手機改了持股、電腦也改了）：交易紀錄與訊號日誌會自動合併；持股與設定會在頁面最上方問你要保留哪一份，不會默默蓋掉。
- **登入前就有的資料**：雲端是空的就直接上傳；雲端也有、內容不同時，交易紀錄與日誌合併，持股請你選。
- **登出**：這個分頁裡的持股、交易紀錄、日誌與財務設定會一起清掉（雲端的不受影響），共用電腦時下一個人看不到。

---

## 四、Google 登入：記住這台裝置（建議，約 10 分鐘）

密碼登入每次重新整理都要再輸入。改用 Google 登入後，Streamlit 會在瀏覽器存一個身分 cookie（約 30 天），手機、電腦各登入一次就好。只有你列在 `ALLOWED_EMAILS` 的 Google 帳號能讀寫資料；密碼登入仍然可以當備用。

### 1. 在 Google Cloud 建立登入用的「OAuth 用戶端」

1. 到 <https://console.cloud.google.com/> → 左上角專案選單 → **新增專案**（名稱隨意，例如 `tw-scanner`）。
2. 左側 **API 和服務 → OAuth 同意畫面**：
   - 使用者類型選 **外部** → 建立。
   - 填應用程式名稱、使用者支援 email、開發人員聯絡 email → 儲存並繼續（範圍不用加）。
   - **測試使用者** 加入你自己的 Gmail（應用程式維持「測試中」即可，只有你會用）。
3. 左側 **憑證 → 建立憑證 → OAuth 用戶端 ID**：
   - 應用程式類型：**網頁應用程式**。
   - **已授權的重新導向 URI** 加入（換成你的 App 網址）：
     ```
     https://你的app名稱.streamlit.app/oauth2callback
     ```
     本機也要用的話，再加一條 `http://localhost:8501/oauth2callback`。
   - 建立後複製 **用戶端 ID** 和 **用戶端密鑰**。

### 2. 產生一串隨機的 cookie 密鑰

在任何有 Python 的地方執行，複製輸出的字串：

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

### 3. 貼進 Streamlit Cloud 的 Secrets

**Manage app → Settings → Secrets**，在原本的 `DATABASE_URL`、`APP_PASSCODE` 下面加上（換成你的值；`[auth]` 那段要放在最後）：

```toml
ALLOWED_EMAILS = ["你的Gmail@gmail.com"]

[auth]
redirect_uri = "https://你的app名稱.streamlit.app/oauth2callback"
cookie_secret = "第 2 步產生的字串"
client_id = "xxxxxxxx.apps.googleusercontent.com"
client_secret = "GOCSPX-xxxxxxxx"
server_metadata_url = "https://accounts.google.com/.well-known/openid-configuration"
```

**Save** → App 重啟後，「設定」頁會出現 **「用 Google 登入」**。

### 常見狀況

- **按下去出現 `redirect_uri_mismatch`**：Google Cloud 填的重新導向 URI 和 secrets 的 `redirect_uri` 要一字不差（包含 `https://`、結尾的 `/oauth2callback`）。
- **出現「存取遭封鎖：這個應用程式尚未通過驗證」**：OAuth 同意畫面的「測試使用者」沒有加入你的 Gmail。
- **登入後顯示「不在允許名單裡」**：`ALLOWED_EMAILS` 沒有這個 Gmail（不分大小寫）。沒設定 `ALLOWED_EMAILS` 時一律不允許，這是刻意的安全預設。
- **想登出這台裝置**：「設定 → 登出」會一併登出 Google 並清掉這個分頁的資料。
- 用 Google 和用密碼登入看到的是**同一份**雲端資料。

## 常見問題

- **沒設定會怎樣？** 持股、交易紀錄、訊號日誌只存在這個瀏覽器分頁（重整會清空，可用匯出備份）。不會寫進伺服器上的檔案：公開部署時伺服器檔案是所有訪客共用的。
- **安全嗎？** 連線走 SSL；只有知道 `APP_PASSCODE` 的人，或 `ALLOWED_EMAILS` 裡的 Google 帳號能登入讀寫。建議密碼別太簡單；用了 Google 登入後，也可以把 `APP_PASSCODE` 拿掉，只留 Google。
- **想多人共用？** 目前是單人（owner 固定）。要開放多人註冊再告知，可升級為每人獨立帳號（Auth + 權限）。
- **本機跑（非雲端）？** 在專案根目錄建 `.streamlit/secrets.toml` 貼上同內容（已在 .gitignore，**勿 commit 進 git**）。本機有 PostgreSQL 也可以用 `postgresql://user@127.0.0.1:5432/db`。
- **資料存在哪？** 一張表 `tw_kv(owner, key, value jsonb, updated_at)`，key 為 holdings / trades / journal / prefs。`updated_at` 同時當版本號，用來發現另一台裝置的修改。
