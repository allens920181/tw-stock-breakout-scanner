# 背景掃描與自動排程

兩種方式，都在「找標的」頁的「背景掃描與自動排程」區塊。

| | 背景掃描 | 自動排程 |
|---|---|---|
| 誰執行 | 這個 App 的伺服器，另開一條執行緒 | GitHub Actions |
| 什麼時候 | 你按下去的時候 | 每個交易日台灣時間 15:40（可改） |
| App 睡著了還能跑嗎 | 不能（App 要醒著） | 可以 |
| 離開頁面會中斷嗎 | 不會，回來按「載入結果」 | 不需要開著 App |
| 結果去哪 | 雲端資料庫（有登入時），否則只在伺服器記憶體 | 雲端資料庫 |

一次下載、同時算好「強勢突破、早期突破、潛伏起漲前」三種策略；同時算出「實證規則」的買進名單與持股檢查（排程才算，因為要逐檔抓月營收）。
只存進場與觀察的股票（每種策略最多 150 檔），雲端用量很小。

## 設定自動排程（只要做一次）

1. 先完成雲端資料庫設定（`docs/雲端設定.md`）。
2. GitHub repo → **Settings → Secrets and variables → Actions → New repository secret**：名稱 `DATABASE_URL`，內容貼和 Streamlit Secrets 同一條 Neon 連線字串。
3. **Actions → 排程掃描 → Run workflow** 手動跑一次。可以選範圍（預設僅普通股）、策略、要不要算實證規則名單。
4. 之後每個交易日自動執行。App 的「找標的」與「今日決策」會出現「排程掃描 MM/DD HH:MM」，按「載入這份結果」即可；「策略驗證 → 實證規則」會直接用排程算好的名單。

### 改時間
編輯 `.github/workflows/scheduled-scan.yml` 的 `cron`（UTC，台灣 = UTC+8）。例如台灣 16:30 → `30 8 * * 1-5`。
GitHub 的排程可能延遲數分鐘到半小時，不是準點；休市日仍會執行，但資料和前一天一樣。

### 命令列
```bash
DATABASE_URL=... uv run python main.py --job --universe twse-common --modes breakout,early --no-rulebook
```

## 限制
- 載入的排程結果只有進場與觀察的股票，沒有 K 線與原始資料，所以不能「用現有資料重新評估」；換策略時請載入該策略的排程結果，或自己按「開始掃描」。
- 排程用你在 App 存到雲端的設定（總資金、風險比例、選股條件）。改了設定，下一次排程才會套用。
- 背景掃描只支援全台股範圍；一次只能跑一個。
- 免費的 Streamlit 主機 App 重啟時，背景掃描會中斷。
- GitHub Actions 的 IP 能不能順利抓到證交所與 Yahoo 的資料，要第一次執行才知道；失敗時看 Actions 的紀錄。
